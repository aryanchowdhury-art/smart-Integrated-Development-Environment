What this IDE is

A local, offline bootstrap launcher for Python projects. It creates a folder, installs a virtual environment, installs dependencies, warns you before running hardware-heavy code, and hands you off to VS Code. It ships with a local Qwen2.5-Coder assistant that runs entirely from disk — no API keys, no network, no usage limits.

One sentence: Double-click → pick a template → 30 seconds later you have a working project in VS Code. That's the entire value.

Installation

Requirements

  • Windows 10 or 11
  • Python 3.9+ installed from python.org with "Add Python to PATH" ticked during installation
  • ~3 GB free disk (the GGUF model is ~1 GB)
  • 4-core CPU, 8 GB RAM minimum (Intel i5 or equivalent)

Build

  1. Double-click build.bat
  2. Wait 3–6 minutes (first run only — subsequent rebuilds are ~2 min)
  3. Launches automatically → dist\ai_ide\ai_ide.exe
Zero manual pip. The batch file auto-installs PyQt6, psutil, llama-cpp-python, and PyInstaller into your global Python if they're missing. You only need to have Python itself.

Run without building

pip install PyQt6 psutil
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
python ai_ide.py

What it's good at

  • "Explain this function" (with 📎 + selection)
  • "Refactor to use a list comprehension" (with 📎)
  • "Write a Flask route that returns JSON with pagination"
  • "Debug: this returns None, why?" (with 📎 + selection)
  • "What does this project do?" (with 📁 on small projects)
  • "How do I run a small LLM on 8 GB without a GPU?"
  • "Write pytest tests for this function"

What it can't do

  • Run code, edit files, or install packages
  • Access the internet (fully offline)
  • See files you didn't attach with 📎 or 📁
  • Handle projects larger than ~2000 lines (context limit)
  • Suggest CUDA-only code (system prompt forbids it)
  • Remember conversations across IDE restarts
  • Replace Copilot / Claude / Cursor for large projects

The 8192-token reality: after the system prompt (~120) and chat history (~600), you have ~7000 tokens for the bundle. That's about 2000 lines of code total. Anything larger and 📁 starts skipping files — you'll see [chat] warning: project context is large in the terminal.

Hardware guardrail

Before running any script, the IDE scans the source for heavy ML/DL patterns:

torch · tensorflow · transformers · .fit( · nn.Module

If any are found, a dialog appears before execution:

┌─────────────────────────────────────────────────────────┐ │ ⚠ Hardware Guardrail │ │ │ │ Heavy ML/DL code detected in the active editor. │ │ │ │ Detected: torch (PyTorch), nn.Module neural network │ │ │ │ Hardware profile "aryan": │ │ • CPU: Intel Core i5, 4 cores — training will saturate │ │ • RAM: 8 GB — large models may swap or OOM │ │ • GPU: integrated Intel UHD only — no CUDA acceleration │ │ │ │ Suggestions: use CPU wheels, small batch sizes, │ │ quantized models, prefer inference over training. │ │ │ │ Run anyway? │ │ │ │ [ Abort ] [ Proceed Anyway ] │ └─────────────────────────────────────────────────────────┘

Abort → nothing runs. Proceed Anyway → the script runs and likely fails with ModuleNotFoundError (torch isn't installed). That's fine — the point is the warning, not running the code.

Note: the guardrail is a source-code regex, not an import check. It fires on code you haven't installed dependencies for. That's intentional — it stops you before you waste time installing 200 MB of torch only to discover it OOMs on your 8 GB machine.

Venv / pip pipeline explained

When you click Setup Venv (or a fresh project auto-fires it), the IDE runs these steps in a background thread:

1. python -m venv .venv
      ↳ self-heals: if ensurepip is missing, downloads get-pip.py
2. .venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
3. If requirements.txt mentions "torch":
      ↳ writes .venv\pip.ini with extra-index-url = https://download.pytorch.org/whl/cpu
4. If requirements.txt exists:
      ↳ .venv\Scripts\python.exe -m pip install -r requirements.txt

Why the CPU-torch step matters

Default pip install torch on Windows pulls the 2.5 GB CUDA wheel. On your machine with no NVIDIA GPU, that fails at import torch because there's no CUDA driver to bind to. The IDE auto-writes a pip.ini that points pip at PyTorch's CPU-only index, giving you the ~200 MB CPU wheel instead.

When does this trigger? Only if requirements.txt contains the word "torch". If you add torch later, click Install Reqs — it re-checks and writes the ini.

What this IDE cannot do

Be realistic about the tool before you commit to it.

The editor is a scratchpad

  • No syntax highlighting
  • No autocomplete / LSP
  • No debugger / breakpoints
  • No find/replace
  • No git integration
  • No multi-file refactoring

Use VS Code for anything beyond the bootstrap phase. That's the point of the "Open in VS Code" button.

The AI is a small local model

  • Not GPT-4 / Claude class
  • No internet access
  • 8192-token context limit
  • No file-system access
  • Can't run code
  • Hallucinates library APIs sometimes

1.5B params is a toy compared to 200B+ models. Verify its output. It's a bootstrap assistant, not a senior dev.

Rebuilding after code changes

If you edit ai_ide.py:

1. Double-click build.bat
2. Wait ~2 minutes (faster than the first build)
3. Test dist\ai_ide\ai_ide.exe

The batch deletes build/ and dist/ automatically, then rebuilds clean.

Rollback

copy ai_ide.py.bak ai_ide.py

The .bak file was created by the patcher — it holds the pre-patch version.

  2. Double-click build.bat
